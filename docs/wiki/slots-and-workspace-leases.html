    Slots and workspace leases

    Citations checked by Claude Sonnet 5.5, separate check: 26 supported, 15 partly supported. Hover a marked citation to see why.

    Capacity in opencode-multiuser is a fixed pool of numbered slots. A workspace is allowed to run a container only while it holds one, and a small number of database rules keep that bookkeeping consistent. This page covers the tables, how a slot is claimed and returned, and which guarantees come from the database rather than from application code.

    The data model

    Two tables carry the lease. Slot is one row per unit of capacity: an integer primary key, an indexed in_use flag and a nullable workspace_id recording the owner models.py 53–57. Workspace is a user's workspace for one project. It points back to the slot with a nullable foreign key slot_id, and carries container_name and a status models.py 60–83.

    The two sides of the lease are therefore stored twice: Slot.in_use/Slot.workspace_id on the slot, and Workspace.slot_id on the workspace. Only the workspace side is a real foreign key; Slot.workspace_id is a plain 36-character string column models.py 55–57 models.py 76. Keeping both in step is the job of the helpers in app/main.py.

    WorkspaceStatus has five states: starting, running, stopping, stopped and error models.py 13–18. Only the first three count as "active", and that distinction is what the database enforces.

    The transitions come from the start handler main.py 692 main.py 709 main.py 717 and from _release_workspace main.py 86–88 main.py 100.

    Seeding the pool

    _seed_slots makes sure a Slot row exists for every id from 1 to settings.max_slots, adding only the missing ones main.py 72–78. It runs at startup from lifespan main.py 289. Because it only adds, lowering max_slots later does not remove existing rows. The code shown does not delete them, so the pool can stay larger than the setting.

    Slot ids matter beyond bookkeeping: workspace_host_port maps a slot id to the loopback port its container is published on, as workspace_host_port_base + slot_id runtime.py 164–165. A slot is thus also a port reservation. Starting a workspace runtime shows where that port is used.

    Claiming a slot

    The /workspaces/start handler does the claim main.py 662–719:

    1. It loads the user's newest workspace row for the project. If that row is STARTING or RUNNING and the runtime looks healthy (secret file present, container running), it just touches the activity timestamp and returns it. Otherwise it releases the stale row first main.py 664–680.
    2. It selects the lowest-numbered free slot. On any database other than SQLite the query adds FOR UPDATE SKIP LOCKED, so concurrent requests lock different rows instead of waiting on or colliding over the same slot main.py 682–685.
    3. With no free slot it answers 503 "No workspace capacity available" main.py 686–687.
    4. It reuses the existing row (resetting status, container name and timestamps) or creates a new one, then marks the slot in_use with the workspace id, and commits main.py 689–704.

    The commit in step 4 happens before the container is started. The lease is therefore durable and visible to other requests while the slow container start runs main.py 703–707. If start_workspace raises, the handler frees the slot and sets the workspace to ERROR, returning HTTP 500 main.py 713–719. It does not clear ws.slot_id on that path, and stop_workspace(ws.container_name) sees a None name because the name is only assigned after a successful start main.py 693 main.py 708 main.py 714–718.

    Returning a slot

    _release_workspace is the single place that undoes a lease. It marks a non-terminal workspace STOPPING and commits, removes the container, clears in_use and workspace_id on the slot, then sets STOPPED, stamps stopped_at, clears container_name and slot_id, records a stop reason and commits once main.py 84–105. The slot release and the final status change land in the same commit, so they cannot be observed half-done.

    Everything that stops work goes through it: the manual stop route main.py 722–732, _stop_user_workspaces for logout and admin actions main.py 170–179 main.py 417–418, the idle reaper main.py 262, and the recycling of runtimes that are no longer usable main.py 110–118 main.py 141. Those last two are covered in Startup, reconciliation and idle reclamation.

    The dashboard derives its capacity numbers straight from the table: total slots and slots where in_use is false main.py 482–484.

    What the database enforces

    The central invariant is one active workspace per user and project. Workspace declares a unique index uq_active_workspace on (user_id, project_slug), restricted by a WHERE clause to rows in STARTING, RUNNING or STOPPING, for both PostgreSQL and SQLite models.py 62–71. STOPPED and ERROR rows are outside the index, so a user can accumulate any number of historical rows for a project but never two live ones. A second concurrent insert for the same pair fails at the database. The start handler shown does not catch that error around its flush or commit main.py 699 main.py 703.

    A fresh database gets the index from the model. An existing one gets it from ensure_active_workspace_index, which runs CREATE UNIQUE INDEX IF NOT EXISTS with the same predicate and skips dialects other than PostgreSQL and SQLite with a warning migrations.py 95–109. That makes it safe to run on every startup.

    Older databases might already hold duplicates, which would make index creation fail. _dedupe_active_workspaces handles this: it orders active rows by user, project and newest first, keeps the first of each pair and releases the rest main.py 145–167. The startup order is deliberate: reconcile, dedupe, then create the index main.py 295–297. A legacy constraint, uq_activeish_workspace, is dropped even earlier, before tables are created migrations.py 83–92 main.py 286.

    What the schema does not enforce is slot exclusivity. The code shown has no unique constraint on Workspace.slot_id models.py 76. Two workspaces never share a slot because the claim path selects only free slots and, on databases other than SQLite, locks the row it picks main.py 682–685.
