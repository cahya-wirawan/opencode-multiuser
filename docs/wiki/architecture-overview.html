    Guide / Foundations

    Architecture overview

    Citations checked by Claude Sonnet 5.5, separate check: 26 supported, 6 partly supported. Hover a marked citation to see why.

    OpenCode Multiuser is one FastAPI process that is both a control plane (accounts, workspaces, admin) and a reverse proxy in front of per-workspace OpenCode containers. This page shows the pieces, follows one browser request to a container, and says where to start reading.

    The main parts

    • Control plane, app/main.py. It creates the FastAPI app with the title "OpenCode Multiuser Gateway" and moves the interactive docs under /_control main.py 309–316. It holds the login and registration routes, the dashboard, the admin and workspace APIs, and the proxy routes. See Authentication and roles for the sign-in side.
    • Gateway, app/gateway.py. proxy_http forwards one HTTP request to the user's selected workspace gateway.py 132–203. See The gateway proxy.
    • Runtime, app/runtime.py. start_workspace starts one isolated container for a workspace in a given slot and returns once it is healthy runtime.py 207–266. See Starting a workspace runtime.
    • Data, app/models.py and app/db.py. The models define users, Slot rows and Workspace rows models.py 26–57. app/db.py builds the engine from settings.database_url and exposes get_db, a per-request session dependency that always closes the session db.py 14–23. Startup creates a partial index over active workspaces (starting, running, stopping) after collapsing duplicates, so the database can enforce one active workspace per user and project main.py 145–147. See Slots and workspace leases.
    • Configuration, app/config.py. Settings is a pydantic-settings model read from environment variables and an optional .env file config.py 5–6. Domain and ports, JWT and cookies, local and OIDC authentication, Podman limits and Traefik options all live there config.py 8–67.
    • Traefik helpers, app/traefik.py. workspace_open_url builds <control_plane_url>/open/<workspace_id> traefik.py 4–5. The app no longer uses per-workspace Traefik files; startup removes leftovers from the older design main.py 292–294. What Traefik does in front of the portal is not visible in the files shown here.

    One request, browser to container

    1. Sign in. login checks a local password and _set_session_cookie stores a token in the session cookie main.py 364–381.
    2. Start a workspace. POST /workspaces/start takes the first free Slot, ordered by id. On non-SQLite databases it locks the row with skip_locked so concurrent starts cannot take the same slot main.py 682–685. It marks the slot and workspace as in use, commits, and then calls start_workspace main.py 701–707. If the start fails, the slot is released and the workspace is marked ERROR main.py 713–719.
    3. Create the container. start_workspace generates a random per-workspace password and writes it to disk runtime.py 213–219. It publishes the container's port 4096 only on 127.0.0.1 at a host port computed from the slot runtime.py 214. The base port is the setting workspace_host_port_base config.py 58. The container also gets that password as OPENCODE_SERVER_PASSWORD runtime.py 247, memory, CPU and PID limits, dropped capabilities, and a read-only root filesystem runtime.py 228–234. It then waits for readiness, and removes the container if the wait fails runtime.py 260–264.
    4. Select the workspace. GET /open/{workspace_id} accepts only a running workspace owned by the caller. It refuses one with no gateway secret file, stamps activity, and sets the workspace cookie before redirecting to / main.py 829–859.
    5. Proxy. Every other path falls through to a catch-all route, which the source says must stay last so the control-plane endpoints remain local main.py 946–948. It requires current_user, resolves the workspace with selected_workspace_for_request, and checks _workspace_runtime_usable main.py 948–957. A workspace whose container is gone is released and the browser is sent back to the dashboard main.py 957–967. Otherwise the request goes to proxy_http main.py 977.
    6. Swap credentials and forward. proxy_http records activity, reads the workspace secret, builds the target URL and forwards the request with headers built by _forward_headers and the workspace password gateway.py 133–138. The body of _forward_headers is not shown here. The response streams back and each chunk refreshes the activity timestamp gateway.py 168–181. A successful HTML response is instead read fully and rewritten to include the portal widget gateway.py 154–166. A connection failure becomes HTTP 502 gateway.py 146–152. WebSockets go through a separate route that hands off to proxy_websocket, whose body is not shown main.py 986–989.

    The browser never sees the workspace password. The portal's session cookie decides who the user is, and the gateway adds the container's own credentials on the way through.

    What happens at startup

    The lifespan context manager validates the auth settings, runs the schema migrations, creates tables, seeds slots, creates the data directories and removes the legacy Traefik routes. It then reconciles database leases with real containers and removes duplicate active workspaces before adding the unique index main.py 281–297. If workspace_idle_timeout_minutes is above zero, it also starts a background reaper task and cancels it on shutdown main.py 298–306. The details are in Startup, reconciliation and idle reclamation.

    Where to open first

    Start with app/main.py. Its routes are the table of contents for the whole system, and the proxy routes at the bottom show how everything connects. Then read app/gateway.py for the request path, app/runtime.py for container creation, and app/models.py for the invariants the database enforces. Keep app/config.py open beside them: the limits, cookie names, ports and timeouts used above are all settings fields.
