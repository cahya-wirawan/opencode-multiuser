    Guide / Workspace lifecycle

    Starting a workspace runtime

    Citations checked by Claude Sonnet 5.5, separate check: 35 supported, 18 partly supported. Hover a marked citation to see why.

    A workspace runtime is one locked-down OpenCode container plus a directory tree on the host. This page follows start_workspace from the on-disk layout through the container flags and the administrator's provider policy to the readiness wait. The slot it is given is explained in Slots and workspace leases. The callers of start_workspace are in app/main.py, which this page's sources do not include.

    On-disk layout

    Everything lives under settings.expanded_data_root, which expands %h and ~ and resolves the path config.py 69–71; the default is ~/.local/share/opencode-multiuser config.py 48. workspace_root returns <data_root>/users/<user_id>/<project_slug> runtime.py 49–52. It first validates the slug against ^[a-zA-Z0-9_.-]+$ and explicitly rejects . and .., so a slug cannot climb out of the user directory runtime.py 15 runtime.py 50–51. A test checks the dot-segment rejection test_gateway.py 114–121.

    workspace_paths creates and returns four persistent directories under that root: workspace, opencode-data, opencode-state and opencode-config runtime.py 55–63. Next to them sit small files managed by other helpers: runtime-secret, last-activity and stop-reason runtime.py 103–104 runtime.py 120–125. The secret and stop-reason files are written with mode 0o600 runtime.py 128–132 runtime.py 147–151. The idle timer reads the mtime of last-activity runtime.py 107–117.

    remove_workspace_data deletes that whole root, but only after checking that the root's parent is exactly the user's directory and that the root is not a symlink; otherwise it raises ValueError runtime.py 92–99. A test confirms only the selected workspace is removed test_gateway.py 101–111.

    Identity, secret and port

    start_workspace derives three values from its arguments runtime.py 207–214:

    • The container name is oc-<slot_id>-<first 12 hex characters of the workspace id>.
    • The OpenCode password is secrets.token_urlsafe(32), generated fresh on every start.
    • The host port comes from workspace_host_port(slot_id), the configured base (41000 by default) plus the slot id runtime.py 164–165 config.py 58.

    Before launching, it runs podman rm -f on that name, because a crash may have left it behind, then clears any previous stop reason and persists the password with write_workspace_secret runtime.py 216–219. That file is how the gateway later learns the password; read_workspace_secret raises a "secret is missing" error if the file is absent runtime.py 154–161. See The gateway proxy for its use.

    Container flags

    The podman run -d argument list is built inline runtime.py 221–248.

    Concern Flags
    Reachability --publish 127.0.0.1:<port>:4096, loopback only, with a comment that nothing outside the host can reach it directly runtime.py 225–227
    Resources --memory, --cpus, --pids-limit from settings, defaults 8g, 4.0 and 1024 runtime.py 228–230 config.py 50–52
    Privileges no-new-privileges, --cap-drop ALL, and a user namespace mapping to uid and gid 10001 runtime.py 231–233
    Filesystem --read-only root with tmpfs mounts at /tmp (1g) and ~/.cache (512m) runtime.py 234–236
    State The four directories bind-mounted read-write with the Z SELinux label runtime.py 237–240
    Auth OPENCODE_SERVER_USERNAME=opencode and OPENCODE_SERVER_PASSWORD runtime.py 246–247

    Because the root filesystem is read-only, the HOME and XDG_* variables point at the writable mounts runtime.py 241–245. OPENCODE_CORS is added only when settings.opencode_cors is non-empty runtime.py 253–254. The image and the serve --hostname 0.0.0.0 --port 4096 command come last runtime.py 255–258. Every Podman call goes through _run, which applies a 90-second timeout and raises RuntimeError with stdout and stderr on a non-zero exit unless check=False runtime.py 25–40.

    The managed provider policy

    Administrators can restrict model providers through two comma-separated settings, opencode_enabled_providers and opencode_disabled_providers. A comment says they are applied as OpenCode managed settings to every workspace and take precedence over project config config.py 64–67. Settings.enabled_provider_ids and Settings.disabled_provider_ids parse them with Settings._provider_ids, which trims whitespace, drops blanks and duplicates, and keeps order config.py 77–93.

    managed_opencode_config_path turns that into a file runtime.py 66–89:

    • It builds a JSON object with the OpenCode $schema and adds enabled_providers and/or disabled_providers only when non-empty. If nothing but the schema remains it returns None runtime.py 68–76. In that case the function does not touch an earlier file in the policy directory.
    • Otherwise it writes <data_root>/policy/opencode.json. The file is the same for every workspace; its path contains no user or project runtime.py 78–80.
    • The write is atomic: it dumps to a temporary file in the same directory, sets mode 0o644, then replaces the target runtime.py 81–88. A reader never sees a half-written policy.

    start_workspace calls it on every start runtime.py 210 and, when a path comes back, mounts it read-only at /etc/opencode/opencode.json runtime.py 249–252. Read-only is what makes the policy "immutable" from inside the container (the docstring uses that word runtime.py 67). Tests check de-duplication, file mode and the :ro,Z mount test_gateway.py 18–53. A policy change applies to workspaces started afterwards. The code shown does not touch running containers.

    The readiness wait

    After run, start_workspace calls wait_workspace_ready runtime.py 259–261. It computes a deadline from workspace_ready_timeout_seconds (45 by default) and builds a Basic header for user opencode runtime.py 169–171 config.py 53. Each loop iteration does the following:

    1. If the container is no longer running, it reads the last 80 log lines and raises "OpenCode container exited before becoming ready" with that text. A crashed container fails fast instead of waiting out the timeout runtime.py 175–178.
    2. It sends GET /global/health to 127.0.0.1:<host_port> with a 2-second timeout. Any 2xx response ends the wait runtime.py 180–191.
    3. A non-2xx status or a connection error is remembered as last_error, the connection is closed, and it sleeps workspace_ready_poll_interval_seconds, 0.5 by default runtime.py 192–199 config.py 54.

    When the deadline passes it raises a RuntimeError naming the timeout, the port and the last error runtime.py 201–204. A test with a fake connection covers the success path test_gateway.py 155–173.

    If the wait raises, start_workspace force-removes the container and re-raises runtime.py 260–264. The secret file written earlier is not removed on that path in the code shown. On success it touches last-activity, so a new workspace does not look idle, and returns a RuntimeResult holding the container name, password and host port runtime.py 265–266 runtime.py 18–22.
