    The gateway proxy

    Citations checked by Claude Sonnet 5.5, separate check: 33 supported, 4 partly supported. Hover a marked citation to see why.

    The gateway is the reverse proxy that sits between the portal's public port and the per-workspace OpenCode containers. This page follows one request through it: which workspace is chosen, how the user's portal credentials are replaced, how the response is streamed or rewritten, and how WebSockets are relayed.

    app/main.py imports proxy_http, proxy_websocket and selected_workspace_for_request from app/gateway.py main.py 16. The route handlers that call them are outside the excerpt shown for this page, so the sections below start where the gateway functions take over. For how the container and its port come to exist, see Starting a workspace runtime; for the slot a workspace holds, see Slots and workspace leases.

    Choosing the workspace

    _find_selected_workspace only considers workspaces that belong to the user and have status RUNNING gateway.py 80–83. The behaviour then depends on whether the client named one:

    • With a selector, it matches either the workspace id or the container name, and answers 404 if nothing matches gateway.py 84–91.
    • Without one, it lists the user's running workspaces, newest first. Zero running gives 409 "No running workspace", and more than one gives 409 asking the caller to pick one. Exactly one is used implicitly gateway.py 93–101.

    selected_workspace_for_request takes the selector from the x-opencode-workspace header and falls back to the workspace cookie gateway.py 104–106. selected_workspace_for_websocket does the same for WebSockets gateway.py 109–111. Because the query always filters by user.id, a selector for someone else's workspace behaves like one that does not exist.

    The backend address is derived from the slot: _backend_http_url raises 503 if the workspace has no slot, and otherwise targets 127.0.0.1 on workspace_host_port(ws.slot_id), keeping the original path and query string gateway.py 114–120. _backend_ws_url builds the equivalent ws:// URL gateway.py 123–129.

    Swapping credentials

    The browser holds a portal session, but OpenCode expects Basic Auth. _forward_headers builds the outgoing header set:

    • It drops hop-by-hop headers plus host, authorization and content-length gateway.py 56–57.
    • It drops x-opencode-workspace, so a client-controlled routing header never reaches OpenCode gateway.py 58–61.
    • It removes the portal's session and workspace cookies through _clean_cookie_header and keeps any other cookies gateway.py 36–48 gateway.py 62–68.
    • It sets authorization from _basic_auth, which encodes the user name opencode with the workspace secret gateway.py 31–33 gateway.py 69.
    • It forces accept-encoding: identity gateway.py 70. This keeps response bodies uncompressed so HTML can be edited later. The widget code also removes any upstream content-encoding when it rewrites a page gateway.py 195–196.

    A test covers the stripping of session, routing and host headers and the cookie filtering test_gateway.py 56–73, and another covers the identity encoding test_gateway.py 204–208.

    Forwarding an HTTP request

    proxy_http does the following:

    1. Resolves the workspace, records activity with touch_workspace_activity, reads the workspace secret and reads the whole request body gateway.py 133–138.
    2. Opens an httpx.AsyncClient that does not follow redirects, has no timeout and ignores proxy environment variables, and sends the request with stream=True gateway.py 140–145.
    3. Converts any httpx.HTTPError into a 502 that names the exception type gateway.py 146–152.

    The recorded activity is what idle reclamation later reads; see Startup, reconciliation and idle reclamation.

    The response takes one of two paths. A 200 response with a text/html content type is read fully, decoded with the upstream charset (default UTF-8), passed through inject_portal_widget and returned as a plain Response gateway.py 154–166. Everything else is streamed chunk by chunk. Each chunk touches the activity file again, and a background task closes the upstream response and client when streaming ends gateway.py 167–181.

    Headers are copied from the raw upstream list so duplicates such as Set-Cookie survive. Hop-by-hop headers and content-length are skipped, since the body length may change gateway.py 183–190. A Location header that starts with the loopback backend origin is rewritten to settings.control_plane_url, so the browser never sees 127.0.0.1 gateway.py 197–201.

    Relaying a WebSocket

    proxy_websocket cannot use the cookie-based dependency that HTTP routes use, so it authenticates itself. It reads the session cookie, accepts a Bearer token in the Authorization header when there is no cookie, and calls load_user_from_token. An unauthenticated socket is closed with code 4401 gateway.py 207–214.

    If workspace selection fails, the code checks whether the selector names a stopped workspace whose stop reason is idle. If so, it closes with code 4409 and a message pointing back to the dashboard. Otherwise the original error is re-raised gateway.py 216–236.

    When selection succeeds, the gateway connects to the container first, with a 15 second open timeout, no message size limit and no proxy. Only after that does it accept the browser's socket gateway.py 237–249. Two coroutines then pump messages:

    • Client to upstream: text and binary frames are forwarded, and the loop stops on a disconnect message gateway.py 251–262.
    • Upstream to client: frames are forwarded with the matching text or bytes call gateway.py 264–270.

    Every frame in either direction counts as activity gateway.py 258–266. asyncio.wait returns when either pump finishes. The other is cancelled, and an exception from the finished one is re-raised gateway.py 272–285. Any exception ends in a close with code 1011 gateway.py 286–290.

    Injecting the portal widget

    inject_portal_widget leaves a page unchanged if it already contains id="oc-mu-portal". Otherwise it inserts portal_markup before the last </body>, found case-insensitively, or appends it when there is none portal.py 103–111. Tests check both the placement and that injecting twice leaves one widget test_gateway.py 176–193.

    portal_markup escapes the project slug and builds a <details> menu with Dashboard, Stop workspace and Logout controls. It also links /_portal/widget.css and /_portal/widget.js portal.py 86–100. The script polls /_portal/status every 30 seconds. It redirects to /login on a 401 and to the dashboard when the workspace is not running. It adds reason=idle when the workspace stopped for inactivity portal.py 57–81. The server routes behind those /_portal/ URLs are not part of the files shown here.
