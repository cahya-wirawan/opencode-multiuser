    Installation, versioning and releases

    Citations checked by Claude Sonnet 5.5, separate check: 38 supported, 6 partly supported. Hover a marked citation to see why.

    This page follows a release from its version number, through the archive that scripts/package-release.sh builds, to what scripts/install.sh does on a host, including what it keeps when you run it again to upgrade.

    One version number

    The application version is a single string in app/version.py, and its docstring calls the module the single source of truth version.py. app/__init__.py re-exports it, so code can read app.__version__ __init__.py 3–5. tests/test_version.py checks that the login and registration pages contain v{__version__} test_version.py 18–20. The installer reads the same line with sed rather than calling scripts/version.py, and aborts if it cannot find it install.sh 56–58.

    Changing it with scripts/version.py

    The script edits app/version.py in place. Two regular expressions define the format: strict MAJOR.MINOR.PATCH with no leading zeros, and the __version__ = "..." assignment line version.py 20–21.

    • read_version finds the assignment, fails with SystemExit if it is missing, and also fails if the value is not valid semver version.py 24–32.
    • write_version validates the new value and replaces the assignment with a single-substitution regex. It aborts unless exactly one replacement happened version.py 41–47.
    • bump increments one component and zeroes the lower ones; any part other than major or minor falls through to patch version.py 50–56. The command line restricts the choice to the three names, so the fall-through is not reachable from the CLI version.py 66.
    • main handles show, set <version> and bump <part>, defaults to show when no subcommand is given, and prints old -> new after a write version.py 59–79.

    Pre-release or build suffixes such as 1.2.3-rc1 are rejected here. The OpenCode engine version is a separate setting, handled in Admin console and engine updates.

    The tests that pin it

    test_application_version_is_semver compares __version__ against a literal string, so a bump through scripts/version.py must be accompanied by an edit to that test test_version.py 13–15. test_version_cli_show runs the script in a subprocess and asserts that its trimmed output equals __version__, which keeps the CLI and the package from drifting test_version.py 23–32.

    Packaging a release

    scripts/package-release.sh asks scripts/version.py show for the version and names the release opencode-multiuser-<version> package-release.sh 6–7. It requires rsync and zip package-release.sh 12–13. It stages a copy of the repository into a temporary directory that is removed on exit package-release.sh 9–10, leaving out .git, virtualenvs, caches, build output and dist package-release.sh 16–25. Then it zips the staged folder into the output directory (default dist) and writes a .sha256 file next to it package-release.sh 27–35. It prints both paths package-release.sh 37–38.

    What the installer does

    scripts/install.sh runs from an extracted release tree install.sh 22. It is written to be re-run, so most of its logic is about deciding which value wins: the environment, the saved file, or a default.

    Preflight

    1. Complete tree. It refuses to continue unless a list of files, including app/portal.py, app/opencode_update.py, app/version.py and uv.lock, exists, to avoid a partial upgrade install.sh 24–32.
    2. Python 3.11+. It uses PYTHON_BIN if set, otherwise tries python3.13, python3.12, python3.11, then python3, and accepts the first that is at least 3.11 install.sh 34–53.
    3. systemd user session. It needs the runtime directory and the user bus socket, and systemctl --user must work install.sh 60–85.
    4. cgroup delegation. cpu, memory and pids controllers must be delegated to the user manager. If the controllers file cannot be read, it only warns install.sh 87–114.
    5. Port. If ss is available and CONTROL_PLANE_PORT is already in use, it stops install.sh 168–175. The control-plane service is stopped just before this check so a previous install does not block itself install.sh 166.

    scripts/check-host.sh is the read-only counterpart for the same host checks. It prints the runtime directory, user bus, cgroup controllers and Podman's cgroup settings, and changes nothing check-host.sh 3–16.

    Settings that survive an upgrade

    At the top, the script records whether each of BASE_DOMAIN, OPENCODE_VERSION, the provider lists, CONTROL_PLANE_PORT, DATA_ROOT and TRAEFIK_DYNAMIC_DIR was set explicitly, using ${VAR+x} install.sh 4–17. If control-plane.env already exists, each value that was not explicit is read back from it install.sh 123–153. Defaults for DATA_ROOT and the Traefik directory apply only afterwards, both must be absolute, and %h is expanded to $HOME install.sh 155–162.

    The env file itself has two paths:

    • Fresh install. It generates a random JWT_SECRET, writes the full file with a PostgreSQL URL, and sets mode 600 install.sh 204–258. The database password is generated once into postgres.env and reused on later runs install.sh 196–202.
    • Upgrade. Existing values are left alone; each missing key is appended with its default via grep -q ... || echo ... >> install.sh 259–297. Explicit DATA_ROOT and TRAEFIK_DYNAMIC_DIR overrides are then written over the saved ones install.sh 298–303.

    Two migrations adjust the public URL: a legacy http://code.example.com default is rewritten, and an https:// URL is rewritten to HTTP when TRAEFIK_TLS is not true install.sh 305–318. An explicit OPENCODE_VERSION or provider-policy override becomes the new saved value install.sh 321–343. The image build later reads the effective value back from the file install.sh 368–371; the admin update flow described in Admin console and engine updates also maintains that setting.

    Copying, building and starting

    The app is copied to ~/opt/opencode-multiuser with rsync -a --delete, excluding .venv and .pytest_cache, and the copy is verified again for the key files install.sh 116–121 install.sh 177–184. Quadlet files go to ~/.config/containers/systemd, with the Traefik file's placeholders for its dynamic and state directories substituted. The control-plane unit and traefik.yml are copied too install.sh 185–194. The Traefik route file is rendered from a template, and old workspace-*.yml routes are deleted, since every workspace now goes through the gateway install.sh 350–358.

    The virtualenv is deleted and recreated on every run, then dependencies come from uv sync --frozen --no-dev install.sh 360–366. The workspace image is built as localhost/opencode-workspace:latest using the effective saved OpenCode version, and the PostgreSQL and Traefik images are pulled install.sh 368–373. Finally it starts the network, PostgreSQL and Traefik units, then enables and restarts the control plane install.sh 375–379.

    Cleaning up stuck containers

    scripts/reset-orphans.sh force-removes containers whose names match oc-<digits>-<hex>, so fixed services such as PostgreSQL and Traefik are untouched reset-orphans.sh 3–4. It only touches Podman; it does not edit the database. How the app reconciles leases with real containers is covered in Startup, reconciliation and idle reclamation.
