    Guide / Workspace lifecycle

    Startup, reconciliation and idle reclamation

    Citations checked by Claude Sonnet 5.5, separate check: 22 supported, 8 partly supported. Hover a marked citation to see why.

    The database and the containers can disagree: a crash, an upgrade or a manual podman command can leave a workspace marked running with no usable container. This page covers how the app prepares the database at startup, and how it keeps leases in line with reality afterwards, both by reconciling stale runtimes and by reclaiming idle ones.

    The startup sequence

    The FastAPI lifespan context manager does all start-up work before the app serves requests. The order matters, and the comments in the code explain several of the steps main.py 281–297.

    Schema preparation

    There is no migration framework. app/migrations.py holds idempotent functions that run on every start.

    • drop_legacy_workspace_constraint removes the old uq_activeish_workspace constraint on PostgreSQL, using IF EXISTS so a fresh database is safe. On SQLite it only logs that it skips the drop migrations.py 83–92. It runs before create_all so the old rule cannot conflict with the newer one main.py 282–288.
    • migrate_user_auth_schema returns immediately if there is no users table, because create_all will build it from the current model migrations.py 21–23. Otherwise it adds the role, provider and OIDC columns. On PostgreSQL it uses ADD COLUMN IF NOT EXISTS and drops NOT NULL on password_hash. On SQLite it adds only the columns that are missing. Other dialects log a warning and are skipped migrations.py 25–56.
    • It then backfills developer and local for empty values, and promotes the oldest user to admin only if no admin exists migrations.py 58–66. On PostgreSQL it adds defaults and NOT NULL, and it creates a partial unique index on the OIDC issuer and subject migrations.py 67–79. See Authentication and roles for what those roles mean.
    • ensure_active_workspace_index creates the unique index uq_active_workspace on (user_id, project_slug), limited to rows in STARTING, RUNNING or STOPPING. It supports only PostgreSQL and SQLite migrations.py 95–109. This index is the database guarantee behind Slots and workspace leases.

    _seed_slots inserts any slot ids from 1 to settings.max_slots that are missing. It never deletes existing ones main.py 72–78.

    The app also removes v5 per-workspace Traefik files with cleanup_legacy_workspace_routes, which deletes workspace-*.yml in the dynamic directory traefik.py 8–14 main.py 292–294.

    Why reconcile and dedupe come before the index

    A unique partial index cannot be built over rows that already violate it. So _dedupe_active_workspaces runs first. For each user and project it keeps the newest active row and releases the rest main.py 145–167. The index is created only afterwards main.py 295–297.

    Reconciling leases with containers

    _workspace_runtime_usable is the test for "this running workspace is real". All of these must hold main.py 110–118:

    • the status is RUNNING
    • it has a slot and a container name
    • the secret file exists
    • container_running is true
    • container_has_workspace_port is true

    The last check runs podman port for 4096/tcp and requires a line equal to 127.0.0.1: plus the slot's host port. A container that exists but is bound to the wrong port therefore counts as stale runtime.py 282–290.

    _reconcile_workspace_runtimes loads every workspace in STARTING, RUNNING or STOPPING and releases each one that is not usable, with reason recycle. It returns the number released main.py 121–143. A STARTING workspace fails the usability test because it is not RUNNING, and the function does not skip it. At startup that is what clears leases left by a crash mid-start. The code shown does not say how this interacts with a start that is genuinely in progress while the periodic pass runs.

    _release_workspace is the single path for freeing a lease. It marks the workspace STOPPING and commits, then stops the container. It then clears in_use and workspace_id on the slot, sets the workspace to STOPPED, clears container_name and slot_id, writes the stop reason and commits main.py 84–105.

    Idle reclamation

    Activity is a file. touch_workspace_activity creates or touches a marker file, and workspace_last_activity returns its mtime in UTC, or None if it does not exist runtime.py 107–117. The gateway touches it on every proxied exchange (see The gateway proxy). Starting or opening a workspace also touches it main.py 678 main.py 849.

    _reap_idle_workspaces does nothing when workspace_idle_timeout_minutes is zero or negative main.py 241–243. Otherwise it computes a cutoff and checks each RUNNING workspace main.py 245–250. Its last activity is the marker mtime, falling back to created_at. A naive timestamp is treated as UTC. A workspace at or before the cutoff is released with reason idle main.py 251–264. The stop reason is written to a stop-reason file runtime.py 128–132.

    That reason is what lets the system explain itself. When a later request cannot find a running workspace, _idle_timeout_response checks for a stopped workspace whose reason is idle. A browser navigation is redirected to /dashboard?reason=idle, and an API call gets a 409 with code workspace_idle_timeout main.py 877–916.

    The background loop

    _idle_reaper_loop sleeps first, using the larger of 5 seconds and workspace_reaper_interval_seconds. It then runs reconciliation and reaping, each in a worker thread via asyncio.to_thread so blocking Podman and database calls do not stall the event loop. Cancellation is re-raised, and any other exception is logged so the loop keeps running main.py 267–277.

    lifespan starts the loop as a named task only when the timeout is positive. On shutdown it cancels the task and awaits it main.py 298–306. Both functions open their own session with SessionLocal rather than using the request-scoped get_db dependency main.py 124 main.py 247 db.py 15–23.
