    Im Leitfaden: Installation, Versionierung und Releases

    Installer und Upgrader für einen Host mit einem einzelnen Benutzerkonto. Aus einem entpackten Release-Verzeichnis gestartet, prüft er vorab Python, die systemd-User-Session und die cgroup-Delegation. Anschließend kopiert er die App nach ~/opt/opencode-multiuser, schreibt oder migriert control-plane.env, rendert die Quadlet- und Traefik-Dateien, baut das Python-venv und das Workspace-Image und startet die Dienste. Er ist dafür gedacht, für Upgrades erneut ausgeführt zu werden: In control-plane.env bereits gespeicherte Einstellungen bleiben erhalten, es sei denn, die zugehörige Variable ist ausdrücklich in der Umgebung gesetzt.

    Zeilen 4–21

    Jeder einstellbare Wert folgt demselben Muster. Wurde die Variable in der Umgebung des Aufrufers gesetzt (${VAR+x} ist auch bei einem leeren Wert nicht leer), wird ein *_EXPLICIT-Flag festgehalten, bevor der Standardwert angewendet wird. Späterer Code nutzt dieses Flag, um eine ausdrückliche Überschreibung von einem Standardwert zu unterscheiden, sodass ein erneuter Lauf gespeicherte Einstellungen nicht mit Standardwerten überschreibt. Nur die Variablen mit einem _EXPLICIT-Flag nehmen an dieser Persistierung teil. CONTROL_PLANE_BIND, TRAEFIK_PUBLIC_PORT, TRAEFIK_ENTRYPOINT und WORKSPACE_HOST_PORT_BASE sind reine Standardwerte.
