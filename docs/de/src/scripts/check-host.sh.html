    Im Leitfaden: Installation, Versionierung und Releases

    Eine rein lesende Diagnose, die ausgibt, ob der aktuelle Linux-Benutzer das mitbringt, was rootless Podman unter systemd benötigt: ein Runtime-Verzeichnis, einen User-D-Bus-Socket, delegierte cgroup-Controller sowie Podmans eigene cgroup-/Runtime-Einstellungen. Es nimmt keine Änderungen vor. install.sh führt ähnliche Preflight-Prüfungen aus und bricht bei einem Fehler ab, während dieses Skript nur berichtet.

    1#!/usr/bin/env bash
    2set -euo pipefail
    3uid=$(id -u)
    4runtime=${XDG_RUNTIME_DIR:-/run/user/$uid}
    Zeile 4

    Verwendet XDG_RUNTIME_DIR, wenn gesetzt, andernfalls den üblichen Pfad /run/user/<uid>, den eine systemd-User-Session bereitstellt.

    5controllers="/sys/fs/cgroup/user.slice/user-${uid}.slice/user@${uid}.service/cgroup.controllers"
    Zeile 5

    Pfad der cgroup-v2-Datei, die die Controller auflistet, die systemd an den user@<uid>.service-Manager dieses Benutzers delegiert hat. Rootless Podman kann CPU-, Speicher- und PID-Limits nur für Controller durchsetzen, die hier aufgeführt sind.

    6​
    7echo "user: $(id -un) (uid=$uid)"
    8echo "runtime: $runtime"
    9[[ -d "$runtime" ]] && echo "runtime dir: OK" || echo "runtime dir: MISSING"
    10[[ -S "$runtime/bus" ]] && echo "user bus: OK" || echo "user bus: MISSING"
    Zeilen 9–10

    Das Idiom [[ test ]] && echo OK || echo MISSING ist unter set -e unbedenklich, weil der Test in einer &&/||-Liste steht. bus wird mit -S geprüft (ist ein Socket), da systemctl --user diesen Socket benötigt.

    11if [[ -r "$controllers" ]]; then
    12 echo "cgroup controllers: $(cat "$controllers")"
    13else
    14 echo "cgroup controllers: unavailable ($controllers)"
    15fi
    Zeilen 11–15

    Die Controller-Datei wird ausgegeben, wenn sie lesbar ist. Falls nicht, meldet das Skript „unavailable“ samt Pfad, statt fehlzuschlagen, denn der Pfad kann auf Hosts ohne cgroup v2 oder ohne User-Manager fehlen.

    16podman info --format 'podman: cgroupVersion={{.Host.CgroupsVersion}} cgroupManager={{.Host.CgroupManager}} runtime={{.Host.OCIRuntime.Name}}' 2>/dev/null || true
    Zeile 16

    Fragt Podman nach cgroup-Version, cgroup-Manager und Namen der OCI-Runtime. 2>/dev/null || true unterdrückt Fehler und hält den Exit-Status bei 0, sodass ein fehlendes oder defektes Podman den Bericht nicht abbricht.
