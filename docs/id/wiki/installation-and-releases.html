    Panduan / Operasional

    Instalasi, versioning, dan rilis

    Sitasi diperiksa oleh Claude Sonnet 5.5, separate check: 38 didukung, 6 didukung sebagian. Arahkan kursor ke sitasi yang bertanda untuk melihat alasannya.

    Halaman ini mengikuti sebuah rilis mulai dari nomor versinya, melalui arsip yang dibangun oleh scripts/package-release.sh, hingga apa yang dilakukan scripts/install.sh pada sebuah host, termasuk apa yang dipertahankannya saat dijalankan lagi untuk upgrade.

    Satu nomor versi

    Versi aplikasi adalah satu string di app/version.py, dan docstring-nya menyebut modul tersebut sebagai satu-satunya sumber kebenaran version.py. app/__init__.py mengekspor ulang versi itu, sehingga kode dapat membaca app.__version__ __init__.py 3–5. tests/test_version.py memeriksa bahwa halaman login dan registrasi berisi v{__version__} test_version.py 18–20. Installer membaca baris yang sama dengan sed alih-alih memanggil scripts/version.py, dan berhenti jika tidak menemukannya install.sh 56–58.

    Mengubahnya dengan scripts/version.py

    Skrip ini mengedit app/version.py di tempat. Dua regular expression mendefinisikan formatnya: MAJOR.MINOR.PATCH yang ketat tanpa nol di depan, dan baris assignment __version__ = "..." version.py 20–21.

    • read_version menemukan assignment, gagal dengan SystemExit jika tidak ada, dan juga gagal jika nilainya bukan semver yang valid version.py 24–32.
    • write_version memvalidasi nilai baru dan mengganti assignment dengan regex substitusi tunggal. Fungsi ini berhenti kecuali tepat satu penggantian terjadi version.py 41–47.
    • bump menaikkan satu komponen dan mengnolkan komponen di bawahnya; bagian apa pun selain major atau minor jatuh ke patch version.py 50–56. Command line membatasi pilihan pada tiga nama tersebut, sehingga fall-through itu tidak dapat dicapai dari CLI version.py 66.
    • main menangani show, set <version>, dan bump <part>, menggunakan show sebagai default ketika tidak ada subcommand, dan mencetak old -> new setelah penulisan version.py 59–79.

    Sufiks pre-release atau build seperti 1.2.3-rc1 ditolak di sini. Versi engine OpenCode adalah setting terpisah, yang dibahas di Konsol admin dan pembaruan engine.

    Test yang mengunci versi

    test_application_version_is_semver membandingkan __version__ dengan string literal, sehingga kenaikan versi melalui scripts/version.py harus disertai penyuntingan pada test tersebut test_version.py 13–15. test_version_cli_show menjalankan skrip dalam subprocess dan menegaskan bahwa outputnya yang sudah dipangkas sama dengan __version__, yang menjaga CLI dan paket agar tidak menyimpang test_version.py 23–32.

    Mengemas rilis

    scripts/package-release.sh meminta versi dari scripts/version.py show dan menamai rilis opencode-multiuser-<version> package-release.sh 6–7. Skrip ini membutuhkan rsync dan zip package-release.sh 12–13. Skrip menyiapkan salinan repositori ke direktori sementara yang dihapus saat keluar package-release.sh 9–10, dengan mengecualikan .git, virtualenv, cache, output build, dan dist package-release.sh 16–25. Kemudian skrip meng-zip folder staging itu ke direktori output (default dist) dan menulis file .sha256 di sampingnya package-release.sh 27–35. Skrip mencetak kedua path tersebut package-release.sh 37–38.

    Apa yang dilakukan installer

    scripts/install.sh dijalankan dari pohon rilis yang sudah diekstrak install.sh 22. Skrip ini ditulis agar dapat dijalankan ulang, sehingga sebagian besar logikanya berkaitan dengan menentukan nilai mana yang menang: environment, file tersimpan, atau default.

    Preflight

    1. Pohon lengkap. Skrip menolak melanjutkan kecuali daftar file, termasuk app/portal.py, app/opencode_update.py, app/version.py, dan uv.lock, ada, untuk menghindari upgrade parsial install.sh 24–32.
    2. Python 3.11+. Skrip memakai PYTHON_BIN jika diatur, jika tidak mencoba python3.13, python3.12, python3.11, lalu python3, dan menerima yang pertama yang minimal 3.11 install.sh 34–53.
    3. Sesi user systemd. Skrip membutuhkan direktori runtime dan socket bus pengguna, dan systemctl --user harus berfungsi install.sh 60–85.
    4. Delegasi cgroup. Controller cpu, memory, dan pids harus didelegasikan ke user manager. Jika file controllers tidak dapat dibaca, skrip hanya memberi peringatan install.sh 87–114.
    5. Port. Jika ss tersedia dan CONTROL_PLANE_PORT sudah dipakai, skrip berhenti install.sh 168–175. Layanan control-plane dihentikan tepat sebelum pemeriksaan ini agar instalasi sebelumnya tidak memblokir dirinya sendiri install.sh 166.

    scripts/check-host.sh adalah pasangan read-only untuk pemeriksaan host yang sama. Skrip ini mencetak direktori runtime, user bus, controller cgroup, dan setting cgroup Podman, dan tidak mengubah apa pun check-host.sh 3–16.

    Setting yang bertahan saat upgrade

    Di bagian atas, skrip mencatat apakah masing-masing BASE_DOMAIN, OPENCODE_VERSION, daftar provider, CONTROL_PLANE_PORT, DATA_ROOT, dan TRAEFIK_DYNAMIC_DIR diatur secara eksplisit, menggunakan ${VAR+x} install.sh 4–17. Jika control-plane.env sudah ada, setiap nilai yang tidak eksplisit dibaca kembali dari file tersebut install.sh 123–153. Default untuk DATA_ROOT dan direktori Traefik baru berlaku sesudahnya, keduanya harus absolut, dan %h diperluas menjadi $HOME install.sh 155–162.

    File env itu sendiri memiliki dua jalur:

    • Instalasi baru. Skrip membuat JWT_SECRET acak, menulis file lengkap dengan URL PostgreSQL, dan mengatur mode 600 install.sh 204–258. Kata sandi database dibuat satu kali ke dalam postgres.env dan dipakai ulang pada eksekusi berikutnya install.sh 196–202.
    • Upgrade. Nilai yang sudah ada dibiarkan; setiap key yang hilang ditambahkan dengan defaultnya melalui grep -q ... || echo ... >> install.sh 259–297. Override eksplisit DATA_ROOT dan TRAEFIK_DYNAMIC_DIR kemudian ditulis menimpa nilai yang tersimpan install.sh 298–303.

    Dua migrasi menyesuaikan URL publik: default lama http://code.example.com ditulis ulang, dan URL https:// ditulis ulang menjadi HTTP ketika TRAEFIK_TLS bukan true install.sh 305–318. Override eksplisit OPENCODE_VERSION atau kebijakan provider menjadi nilai tersimpan yang baru install.sh 321–343. Build image kemudian membaca kembali nilai efektifnya dari file install.sh 368–371; alur pembaruan admin yang dijelaskan di Konsol admin dan pembaruan engine juga mengelola setting tersebut.

    Menyalin, membangun, dan memulai

    Aplikasi disalin ke ~/opt/opencode-multiuser dengan rsync -a --delete, mengecualikan .venv dan .pytest_cache, dan salinan itu diverifikasi lagi untuk file-file kunci install.sh 116–121 install.sh 177–184. File Quadlet masuk ke ~/.config/containers/systemd, dengan placeholder pada file Traefik untuk direktori dinamis dan state-nya disubstitusi. Unit control-plane dan traefik.yml juga disalin install.sh 185–194. File rute Traefik dirender dari template, dan rute lama workspace-*.yml dihapus, karena setiap workspace kini melewati gateway install.sh 350–358.

    Virtualenv dihapus dan dibuat ulang pada setiap eksekusi, lalu dependensi diambil dari uv sync --frozen --no-dev install.sh 360–366. Image workspace dibangun sebagai localhost/opencode-workspace:latest memakai versi OpenCode tersimpan yang efektif, dan image PostgreSQL dan Traefik di-pull install.sh 368–373. Terakhir skrip memulai unit network, PostgreSQL, dan Traefik, lalu mengaktifkan dan me-restart control plane install.sh 375–379.

    Membersihkan container yang macet

    scripts/reset-orphans.sh menghapus paksa container yang namanya cocok dengan oc-<digits>-<hex>, sehingga layanan tetap seperti PostgreSQL dan Traefik tidak tersentuh reset-orphans.sh 3–4. Skrip ini hanya menyentuh Podman; tidak mengedit database. Bagaimana aplikasi merekonsiliasi lease dengan container sungguhan dibahas di Startup, rekonsiliasi, dan pemulihan saat idle.
