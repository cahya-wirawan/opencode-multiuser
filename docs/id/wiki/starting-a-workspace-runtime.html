    Panduan / Siklus hidup workspace

    Menjalankan runtime workspace

    Sitasi diperiksa oleh Claude Sonnet 5.5, separate check: 35 didukung, 18 didukung sebagian. Arahkan kursor ke sitasi yang bertanda untuk melihat alasannya.

    Runtime workspace adalah satu container OpenCode yang dikunci ketat ditambah sebuah pohon direktori di host. Halaman ini mengikuti start_workspace mulai dari tata letak di disk, melalui flag container dan kebijakan provider dari administrator, hingga penantian kesiapan. Slot yang diberikan kepadanya dijelaskan di Slot dan lease workspace. Pemanggil start_workspace ada di app/main.py, yang tidak termasuk dalam sumber halaman ini.

    Tata letak di disk

    Semuanya berada di bawah settings.expanded_data_root, yang mengekspansi %h dan ~ serta me-resolve path-nya config.py 69–71; nilai default-nya adalah ~/.local/share/opencode-multiuser config.py 48. workspace_root mengembalikan <data_root>/users/<user_id>/<project_slug> runtime.py 49–52. Fungsi ini lebih dulu memvalidasi slug terhadap ^[a-zA-Z0-9_.-]+$ dan secara eksplisit menolak . dan .., sehingga slug tidak bisa naik keluar dari direktori user runtime.py 15 runtime.py 50–51. Sebuah test memeriksa penolakan segmen titik tersebut test_gateway.py 114–121.

    workspace_paths membuat dan mengembalikan empat direktori persisten di bawah root itu: workspace, opencode-data, opencode-state, dan opencode-config runtime.py 55–63. Di samping direktori-direktori itu terdapat file kecil yang dikelola helper lain: runtime-secret, last-activity, dan stop-reason runtime.py 103–104 runtime.py 120–125. File secret dan file stop-reason ditulis dengan mode 0o600 runtime.py 128–132 runtime.py 147–151. Timer idle membaca mtime dari last-activity runtime.py 107–117.

    remove_workspace_data menghapus seluruh root itu, tetapi hanya setelah memeriksa bahwa parent dari root tersebut tepat sama dengan direktori user dan bahwa root bukan symlink; jika tidak, fungsi ini melempar ValueError runtime.py 92–99. Sebuah test memastikan hanya workspace yang dipilih yang dihapus test_gateway.py 101–111.

    Identitas, secret, dan port

    start_workspace menurunkan tiga nilai dari argumennya runtime.py 207–214:

    • Nama container adalah oc-<slot_id>-<first 12 hex characters of the workspace id>.
    • Password OpenCode adalah secrets.token_urlsafe(32), dibuat baru pada setiap start.
    • Port host berasal dari workspace_host_port(slot_id), yaitu base yang dikonfigurasi (default 41000) ditambah id slot runtime.py 164–165 config.py 58.

    Sebelum meluncurkan container, fungsi ini menjalankan podman rm -f pada nama tersebut, karena crash mungkin meninggalkannya, lalu menghapus stop reason sebelumnya dan menyimpan password dengan write_workspace_secret runtime.py 216–219. File itulah yang dipakai gateway untuk mengetahui password di kemudian hari; read_workspace_secret melempar error "secret is missing" jika file tidak ada runtime.py 154–161. Lihat Proxy gateway untuk penggunaannya.

    Flag container

    Daftar argumen podman run -d disusun secara inline runtime.py 221–248.

    Aspek Flag
    Keterjangkauan --publish 127.0.0.1:<port>:4096, hanya loopback, dengan komentar bahwa tidak ada pihak di luar host yang dapat menjangkaunya secara langsung runtime.py 225–227
    Resource --memory, --cpus, --pids-limit dari settings, default 8g, 4.0, dan 1024 runtime.py 228–230 config.py 50–52
    Privilege no-new-privileges, --cap-drop ALL, dan user namespace yang dipetakan ke uid dan gid 10001 runtime.py 231–233
    Filesystem Root --read-only dengan mount tmpfs di /tmp (1g) dan ~/.cache (512m) runtime.py 234–236
    State Keempat direktori di-bind-mount secara read-write dengan label SELinux Z runtime.py 237–240
    Auth OPENCODE_SERVER_USERNAME=opencode dan OPENCODE_SERVER_PASSWORD runtime.py 246–247

    Karena root filesystem bersifat read-only, variabel HOME dan XDG_* diarahkan ke mount yang dapat ditulis runtime.py 241–245. OPENCODE_CORS ditambahkan hanya jika settings.opencode_cors tidak kosong runtime.py 253–254. Image dan perintah serve --hostname 0.0.0.0 --port 4096 berada paling akhir runtime.py 255–258. Setiap panggilan Podman melewati _run, yang menerapkan timeout 90 detik dan melempar RuntimeError beserta stdout dan stderr jika exit code bukan nol, kecuali check=False runtime.py 25–40.

    Kebijakan provider terkelola

    Administrator dapat membatasi provider model lewat dua pengaturan yang dipisahkan koma, opencode_enabled_providers dan opencode_disabled_providers. Sebuah komentar menyatakan bahwa keduanya diterapkan sebagai managed settings OpenCode ke setiap workspace dan lebih diutamakan daripada konfigurasi project config.py 64–67. Settings.enabled_provider_ids dan Settings.disabled_provider_ids mem-parsenya dengan Settings._provider_ids, yang memangkas spasi, membuang entri kosong dan duplikat, serta mempertahankan urutan config.py 77–93.

    managed_opencode_config_path mengubahnya menjadi sebuah file runtime.py 66–89:

    • Fungsi ini membangun objek JSON dengan $schema OpenCode dan menambahkan enabled_providers dan/atau disabled_providers hanya jika tidak kosong. Jika yang tersisa hanya schema, fungsi mengembalikan None runtime.py 68–76. Dalam kasus itu fungsi tidak menyentuh file lama di direktori kebijakan.
    • Jika tidak, fungsi menulis <data_root>/policy/opencode.json. File ini sama untuk setiap workspace; path-nya tidak memuat user maupun project runtime.py 78–80.
    • Penulisannya atomik: fungsi menulis ke file sementara di direktori yang sama, menyetel mode 0o644, lalu me-replace target runtime.py 81–88. Pembaca tidak pernah melihat kebijakan yang tertulis setengah jadi.

    start_workspace memanggilnya pada setiap start runtime.py 210 dan, ketika sebuah path dikembalikan, me-mount-nya secara read-only di /etc/opencode/opencode.json runtime.py 249–252. Sifat read-only itulah yang membuat kebijakan tersebut "immutable" dari dalam container (docstring memakai kata itu runtime.py 67). Test memeriksa de-duplikasi, mode file, dan mount :ro,Z test_gateway.py 18–53. Perubahan kebijakan berlaku untuk workspace yang dijalankan sesudahnya. Kode yang ditampilkan tidak menyentuh container yang sedang berjalan.

    Penantian kesiapan

    Setelah run, start_workspace memanggil wait_workspace_ready runtime.py 259–261. Fungsi ini menghitung deadline dari workspace_ready_timeout_seconds (default 45) dan membangun header Basic untuk user opencode runtime.py 169–171 config.py 53. Setiap iterasi loop melakukan hal berikut:

    1. Jika container tidak lagi berjalan, fungsi membaca 80 baris log terakhir dan melempar "OpenCode container exited before becoming ready" beserta teks log itu. Container yang crash langsung gagal alih-alih menunggu sampai timeout habis runtime.py 175–178.
    2. Fungsi mengirim GET /global/health ke 127.0.0.1:<host_port> dengan timeout 2 detik. Respons 2xx apa pun mengakhiri penantian runtime.py 180–191.
    3. Status non-2xx atau error koneksi disimpan sebagai last_error, koneksi ditutup, lalu fungsi tidur selama workspace_ready_poll_interval_seconds, default 0.5 runtime.py 192–199 config.py 54.

    Ketika deadline terlewati, fungsi melempar RuntimeError yang menyebutkan timeout, port, dan error terakhir runtime.py 201–204. Sebuah test dengan koneksi palsu mencakup jalur sukses test_gateway.py 155–173.

    Jika penantian melempar exception, start_workspace menghapus container secara paksa dan melempar ulang exception tersebut runtime.py 260–264. File secret yang ditulis sebelumnya tidak dihapus pada jalur itu dalam kode yang ditampilkan. Jika berhasil, fungsi menyentuh last-activity agar workspace baru tidak tampak idle, lalu mengembalikan RuntimeResult yang berisi nama container, password, dan port host runtime.py 265–266 runtime.py 18–22.
