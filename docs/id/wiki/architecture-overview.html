    Gambaran arsitektur

    Sitasi diperiksa oleh Claude Sonnet 5.5, separate check: 26 didukung, 6 didukung sebagian. Arahkan kursor ke sitasi yang bertanda untuk melihat alasannya.

    OpenCode Multiuser adalah satu proses FastAPI yang sekaligus menjadi control plane (akun, workspace, admin) dan reverse proxy di depan container OpenCode per workspace. Halaman ini menunjukkan bagian-bagiannya, mengikuti satu permintaan browser hingga ke container, dan menjelaskan dari mana sebaiknya mulai membaca.

    Bagian-bagian utama

    • Control plane, app/main.py. Berkas ini membuat app FastAPI dengan judul "OpenCode Multiuser Gateway" dan memindahkan dokumentasi interaktif ke bawah /_control main.py 309–316. Di sini terdapat rute login dan registrasi, dashboard, API admin dan workspace, serta rute proxy. Lihat Autentikasi dan peran untuk sisi sign-in.
    • Gateway, app/gateway.py. proxy_http meneruskan satu permintaan HTTP ke workspace yang dipilih pengguna gateway.py 132–203. Lihat Proxy gateway.
    • Runtime, app/runtime.py. start_workspace memulai satu container terisolasi untuk sebuah workspace pada slot tertentu dan kembali setelah container sehat runtime.py 207–266. Lihat Memulai runtime workspace.
    • Data, app/models.py dan app/db.py. Model mendefinisikan pengguna, baris Slot, dan baris Workspace models.py 26–57. app/db.py membangun engine dari settings.database_url dan menyediakan get_db, dependency sesi per permintaan yang selalu menutup sesinya db.py 14–23. Saat startup, dibuat sebuah partial index atas workspace aktif (starting, running, stopping) setelah duplikat digabungkan, sehingga database dapat menegakkan satu workspace aktif per pengguna dan proyek main.py 145–147. Lihat Slot dan lease workspace.
    • Konfigurasi, app/config.py. Settings adalah model pydantic-settings yang dibaca dari variabel lingkungan dan file .env opsional config.py 5–6. Domain dan port, JWT dan cookie, autentikasi lokal dan OIDC, batas Podman, serta opsi Traefik semuanya berada di sana config.py 8–67.
    • Helper Traefik, app/traefik.py. workspace_open_url membangun <control_plane_url>/open/<workspace_id> traefik.py 4–5. Aplikasi tidak lagi memakai file Traefik per workspace; startup menghapus sisa-sisa dari desain lama main.py 292–294. Apa yang dilakukan Traefik di depan portal tidak terlihat di berkas-berkas yang ditampilkan di sini.

    Satu permintaan, dari browser ke container

    1. Sign in. login memeriksa kata sandi lokal dan _set_session_cookie menyimpan token di cookie sesi main.py 364–381.
    2. Memulai workspace. POST /workspaces/start mengambil Slot bebas pertama, berurutan menurut id. Pada database selain SQLite, baris tersebut dikunci dengan skip_locked sehingga permintaan start yang bersamaan tidak bisa mengambil slot yang sama main.py 682–685. Slot dan workspace ditandai sedang dipakai, di-commit, lalu start_workspace dipanggil main.py 701–707. Jika start gagal, slot dilepaskan dan workspace ditandai ERROR main.py 713–719.
    3. Membuat container. start_workspace membuat kata sandi acak per workspace dan menuliskannya ke disk runtime.py 213–219. Fungsi ini mempublikasikan port 4096 container hanya pada 127.0.0.1 di port host yang dihitung dari slot runtime.py 214. Port dasarnya adalah setting workspace_host_port_base config.py 58. Container juga menerima kata sandi itu sebagai OPENCODE_SERVER_PASSWORD runtime.py 247, batas memori, CPU, dan PID, capability yang dihapus, serta root filesystem read-only runtime.py 228–234. Setelah itu fungsi menunggu hingga siap, dan menghapus container jika penantian gagal runtime.py 260–264.
    4. Memilih workspace. GET /open/{workspace_id} hanya menerima workspace yang sedang berjalan dan dimiliki pemanggil. Permintaan ditolak jika tidak ada file rahasia gateway, mencatat aktivitas, dan mengatur cookie workspace sebelum mengalihkan ke / main.py 829–859.
    5. Proxy. Setiap path lain jatuh ke rute catch-all, yang menurut sumbernya harus tetap berada paling akhir agar endpoint control-plane tetap lokal main.py 946–948. Rute ini memerlukan current_user, menentukan workspace dengan selected_workspace_for_request, dan memeriksa _workspace_runtime_usable main.py 948–957. Workspace yang container-nya sudah hilang akan dilepaskan dan browser dikembalikan ke dashboard main.py 957–967. Jika tidak, permintaan diteruskan ke proxy_http main.py 977.
    6. Menukar kredensial dan meneruskan. proxy_http mencatat aktivitas, membaca rahasia workspace, membangun URL target, dan meneruskan permintaan dengan header yang dibangun oleh _forward_headers serta kata sandi workspace gateway.py 133–138. Isi _forward_headers tidak ditampilkan di sini. Respons di-stream kembali dan setiap potongan memperbarui stempel waktu aktivitas gateway.py 168–181. Respons HTML yang berhasil justru dibaca penuh dan ditulis ulang agar menyertakan widget portal gateway.py 154–166. Kegagalan koneksi menjadi HTTP 502 gateway.py 146–152. WebSocket melewati rute terpisah yang menyerahkan ke proxy_websocket, yang isinya tidak ditampilkan main.py 986–989.

    Browser tidak pernah melihat kata sandi workspace. Cookie sesi portal menentukan siapa penggunanya, dan gateway menambahkan kredensial milik container itu sendiri saat permintaan lewat.

    Apa yang terjadi saat startup

    Context manager lifespan memvalidasi setting autentikasi, menjalankan migrasi skema, membuat tabel, mengisi slot, membuat direktori data, dan menghapus rute Traefik lama. Setelah itu ia merekonsiliasi lease database dengan container sungguhan dan menghapus workspace aktif yang duplikat sebelum menambahkan unique index main.py 281–297. Jika workspace_idle_timeout_minutes lebih dari nol, ia juga memulai task reaper di latar belakang dan membatalkannya saat shutdown main.py 298–306. Detailnya ada di Startup, rekonsiliasi, dan pemulihan saat idle.

    Dari mana mulai membuka

    Mulailah dengan app/main.py. Rute-rutenya adalah daftar isi untuk seluruh sistem, dan rute proxy di bagian bawah menunjukkan bagaimana semuanya terhubung. Lalu baca app/gateway.py untuk jalur permintaan, app/runtime.py untuk pembuatan container, dan app/models.py untuk invarian yang ditegakkan database. Biarkan app/config.py tetap terbuka di sampingnya: batas, nama cookie, port, dan timeout yang dipakai di atas semuanya adalah field settings.
